# Project showcase

The Projects route renders workbook-backed records as static-first cards. The workbook owns membership, order, copy, and destinations. `src/features/projects/` owns the known-ID preview registry, preview presentation, action selection, diagrams, loading profiles, and style sheet. No browser request goes to GitHub or the workbook.

## Preview and action contract

Three known IDs use captured public-homepage screenshots at their existing `*-concept.webp` paths for workbook compatibility. Their typed registry records the reviewed desktop dimensions plus an optional local `*-mobile.webp` source for the `720px` and below frame. The responsive sources preserve their distinct capture proportions: current desktop captures are Compliance `1280 × 800`, NotePal `1272 × 795`, and Tergion `1280 × 800`; their current narrow captures are `480 × 360`, `472 × 354`, and `480 × 360`. Clair uses the supplied `793 × 463` desktop screenshot intact at the same path and has no mobile alternative. The media frame is `16:10` above `720px` and `4:3` at or below it. The three website captures use `object-fit: cover` to fill their matched frames without distortion; Clair remains contained and uncropped.

LeetNotes uses a repository-native HTML/SVG preview of one selected published-sheet row: `Two Sum`, `Hash map`, and `Python`. It shows the generated `Notes/blind75.md`, `Notes/neetcode150.md`, `Problems/README.md`, and `Problems/0001. Two Sum/solution1.py` outputs with a scheduled sync connector. It makes no runtime-metric or interactive-application claim. `leetnotes-concept.webp` is its separately captured static fallback asset.

The card header has a noninteractive badge: green `Live site` for Compliance, NotePal, and Tergion; blue `Installable` for Clair; and neutral `Scheduled` for LeetNotes. Unknown IDs retain their authored image and text without a badge or invented workflow.

A thin inset semantic divider separates the visual controls from the footer. The action selector stays source-first below each card: Source code, Live demo, then Download. Preview media links choose Live demo, then Download, then Source code. Workflow diagrams always link Source code. Release detection is local to the Project selector and accepts explicit download/release/installer labels or a structural GitHub `/owner/repo/releases/...` URL before generic GitHub source classification.

## Interaction and no-JavaScript behavior

Each known card starts on its preview. One centered native 44px button beneath the frame changes between `How it works` and `Preview`; both labels occupy the same intrinsic button width with generous horizontal padding and crossfade over `180ms` without moving focus. There is no visible destination hint or directional-arrow copy. Enter and Space use native button behavior. Arrow keys, Home, and End work only while that control is focused. The media rotor turns from `rotateY(0deg)` to `rotateY(-180deg)` over `520ms cubic-bezier(.65, 0, .35, 1)`; a rapid toggle reverses from the current presentation. Its two mounted, individually clipped faces hide their reverse sides, and the inactive face is `aria-hidden` and inert. Reduced motion applies the selected face immediately. There are no tab roles, autoplay, animation library, or height transition.

Static export and no-JavaScript routes render `ProjectStaticVisual`: a linked preview followed by an openable native `How it works` disclosure whose diagram links to source. The shared shell swaps this server-rendered fallback in for the streamed route when scripting is unavailable.

## Maintenance

When changing a project record, change the workbook or template and regenerate. When changing preview bytes, keep their existing public paths, update the registry dimensions and meaningful alt text, then review desktop and narrow frames in every palette. Re-run the relevant unit, browser, skeleton, generated-content, documentation, lint, type, and build checks.
