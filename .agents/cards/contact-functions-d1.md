# Contact Functions and D1

Owns [contact delivery](../../functions/api/contact.ts), [verification](../../functions/api/contact/verify.ts), [shared Function facade](../../functions/_shared/contact.ts), [request parsing](../../functions/_shared/contact/request.ts), [configuration](../../functions/_shared/contact/config.ts), [payload](../../functions/_shared/contact/payload.ts), [ticket](../../functions/_shared/contact/ticket.ts), [DNS](../../functions/_shared/contact/dns.ts), [reservation](../../functions/_shared/contact/reservation.ts), [delivery](../../functions/_shared/contact/delivery.ts), [transport](../../functions/_shared/contact/transport.ts), [reservation migration](../../migrations/0001_contact_rate_reservations.sql), and [payload-fingerprint migration](../../migrations/0002_contact_payload_fingerprint.sql). The direction is request/config/payload and ticket checks into endpoint orchestration, then DNS/reservation/delivery/transport; migrations are append-only.

Read [endpoint contract](../../docs/security/CONTACT_SYSTEM.md#endpoint-contract) and [endpoint change rules](../../docs/security/SECURITY.md#adding-or-changing-an-endpoint). Reuse [shared contracts](../../functions/_shared/contact/contracts.ts) and browser-independent [validation](../../src/lib/contact/validation.ts).

Validate with [delivery tests](../../functions/api/contact.test.ts), [verification tests](../../functions/api/contact/verify.test.ts), and [D1 integration](../../scripts/d1Reservation.integration.test.ts): `npm run test -- functions/api/contact.test.ts functions/api/contact/verify.test.ts scripts/d1Reservation.integration.test.ts`. Broaden to `npm run test:priority`, then `npm run verify:full` for migration, provider, or release-boundary changes.
