# Portfolio validation

Use this skill when adding or changing tests, validation scripts, browser coverage, CI commands, or a release-quality gate.

For candidate selection, snapshot transfer, browser partitioning or rerun evidence, read [CI input and evidence contracts](../../../docs/quality/CI_CONTRACTS.md). The checked-in workflow resolves one candidate, restores immutable original-producer snapshots, runs every full application unit for pull requests, and requires independent source-security receipts even for no-op plans. Rerun tests must distinguish a retained provider copy from a later physical execution: a new execution needs new exact evidence, and malformed or ambiguous copy history fails closed. Preserve that semantic graph and its failure-path tests; module fixtures alone do not prove that a hosted runner or provider enforces it.

Read [Testing](../../../docs/quality/TESTING.md) and [system decisions](../../knowledge/SYSTEM_DECISIONS.md). Start with the closest meaningful unit, integration, or browser contract, then expand only when the changed behavior crosses a boundary. Keep workflow-contract tests synchronized with every CI trigger, permission, artifact, or command change.

Run documentation validation, lint, type checking, focused tests, and the relevant build before handoff. For Research mobile caption or fullscreen changes, also run `npm run test:e2e:research:webkit` after installing WebKit; for Projects responsive previews or the 3D switcher, run `npm run test:e2e:projects:webkit`. Chromium mobile cases remain part of the existing priority suites. WebKit emulation does not replace a recorded physical iPhone Safari check. `npm run verify:priority` is a pull-request-sized **local** gate; reserve `npm run verify:full` for a local release candidate, since it includes local D1 integration and every Chromium contract. The workflow does not substitute that local priority tier for pull-request validation: it runs the complete unit suite, exact Chromium shard/visual assignments, and Firefox/WebKit selection from the same accepted snapshot. Run the latter on Ubuntu 24.04 when its Linux visual baseline is relevant. Use browser tests for focus, scroll, responsive geometry, fixed positioning, rendering, and painted transitions. Keep deterministic runners bounded when external emulation or browser timing needs isolation; select a unique `PLAYWRIGHT_PORT` for concurrent worktrees, fix the scheduling source rather than weakening assertions or raising timeouts without evidence.

For browser accessibility and static-export payload changes, run the matching focused command: `test:e2e:accessibility` scans every public route plus selected open states in Chromium, while the narrow `test:e2e:critical:firefox` and `test:e2e:critical:webkit` commands cover navigation, dialog, theme, and mocked-contact recovery. Run `test:quality:properties` and `test:quality:mutations` when contact boundary guards change. After `build:generated`, run `test:quality:payload`; its checked-in baseline is a reviewed upper bound for route HTML, initial JavaScript, shared framework, and role-specific Research assets, never a value to raise merely to make a build pass. These focused commands remain separate from the stable CI tier until the workflow orchestration explicitly selects them.

Browser tests also run against strict live-workbook builds. Derive expected authored values and optional-field presence from the existing generated-content selectors; keep template-specific copy and date examples in deterministic fixture tests. Assert that expected fields render, then check their layout, rather than skipping assertions solely because a field is absent from the DOM. Preserve sampled reversal boundaries when testing interrupted animation so runner speed cannot discard the state being verified.

For skeleton geometry, transition semantics, visual baselines, or the browser skeleton gate, read [Skeleton regression](../portfolio-skeleton-regression/SKILL.md) before changing anything. Its Linux-only visual baseline and three-part aggregate contract are mandatory.

When feature files move, update local priority directories, required-file discovery, and the CI browser assignment discovery with the new owners; run the resolved import-graph contract and preserve existing browser selection. For route fallbacks, validate every exported route with JavaScript disabled and confirm native Research media, Home education, Projects disclosures, and footer links remain usable.
